# 风格样本库与同步协议

风格库与 Skill 放在同一可迁移仓库中，本机是工作副本，GitHub 是同步备份。样本库的作用是提供当前写作任务的具体参照，不是把大量文章一次性塞进上下文。按[叙事模式分类与自动选择](style-taxonomy.md)给研究材料建立模式和维度索引。

## 内容分层

- 完整文章研究：用于建立时理解一篇文章中问题链、物件复用、判断延迟和结尾回收；平时调用对应的结构笔记。
- 功能样本：按开头引申、事实转解释、问题链转折、声线切换和结尾回收分类；每条注明出处、上下文任务、可迁移机制和不能照搬的表面特征。
- 失败对照：保存不合格原创、具体偏差、合格改写和修改理由；写新段前优先读取一条相近失败对照。
- 个人偏好与迁移实验：记录用户明确确认的审美判断、试写结果和版本变化。

## 调用规则

写作前先确定这一段的任务，再调用一条最相近的失败对照；只有确实需要节奏或转场参照时，才调用一条功能样本。不要同时加载大量样本，避免平均化成“谁都不像”的综合腔。完整文章不作为每轮生成的提示词，而作为建库时的研究依据。

## 公开与同步边界

公开仓库可以放 Skill、原创分析、原创迁移、失败对照、结构笔记和必要的短引用。完整他人文案、连续大段字幕、公司内部材料、客户信息和未经核实的敏感指控需单独评估版权与隐私风险。技术上保持线上线下同一仓库，内容上仍需遵守公开边界。

## 漂移记录

用户指出“不像”时，记录原段、偏差层（结构、材料、句子、视角或节奏）、目标机制、改写结果和下次触发条件。新记录优先用于下一次相同任务的检查，不把一次审美意见泛化成所有题材的硬规则。
