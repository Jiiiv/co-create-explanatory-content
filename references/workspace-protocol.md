# 工作台与版本规范

## 适用时机

当用户已经进入一个具体选题、要求保存进度，或当前工作区明显用于持续内容创作时，建立并维护内容项目。只有概念性探讨、尚未形成具体选题时，可以先在对话内维护状态，不急着创建空目录。

创建或修改文件前先用一句话说明将要变更的文件和范围。只写入当前工作区或用户明确指定的位置，不覆盖无关文件，不上传外部服务。

## 推荐结构

```text
内容项目/主题/
|-- 创作工作台.md
|-- 灵感池.md
|-- 材料与来源.md
|-- 当前逐字稿.md
`-- 历史版本/
```

如果项目已有相同职责的文件，沿用现有命名和组织，不创建重复体系。

## 文件职责

### 创作工作台.md

作为当前内容的单一状态来源，记录：

- 目标受众、平台、预计时长及已确认限制；
- 核心问题与中心命题；
- 当前提纲和每部分任务；
- 观点归属与状态；
- 未决问题、待核项和下一步；
- 最近一次重要更新时间。

不要把完整逐字稿复制进工作台。

### 灵感池.md

保存尚未决定采用的标题、开场、案例、比喻、支线、反方和表达片段。注明提出者或来源及当前状态。进入正式结构或被放弃后更新状态，不要静默删除。

### 材料与来源.md

保存会被稿件实际使用或可能影响判断的材料。每项记录具体主张、来源链接、来源类型、核查状态、使用位置和必要备注。未经核实的材料不能因为进入此文件而被视为事实。

### 当前逐字稿.md

只保存唯一当前有效的完整口播正文。它应反映最新命题和结构，不保留已经废弃的段落，也不混入大量工作批注；必要状态用简短标记表示。

### 历史版本/

只在中心命题改变、结构重建、候选稿冻结或用户明确要求时保存。普通措辞修改不创建版本。文件名应能识别日期和节点，例如 `2026-09-05-候选稿-v1.md`。

## 更新频率

“每轮内容向前生长”不等于每轮都写磁盘。

- 每轮有效讨论：更新对话中的当前状态。
- 重要观点确认、结构变化、材料核实或正文形成较大段落：同步相关文件。
- 暂停或结束本次共创：保存工作台、来源和当前逐字稿。
- 中断后恢复：先读取工作台、当前逐字稿和相关来源，再继续讨论；不要要求用户复述已解决内容。

## 状态与所有权

统一使用以下状态，必要时可简写但不能混淆：

- 用户确认观点
- 用户真实观察
- AI创作提案
- 共同形成的判断
- 已核事实
- 暂定假设
- 待核内容
- 已放弃方向

AI提案经用户明确认可后才能更新为正式立场。用户没有回应不等于确认。个人长期偏好只有在用户明确确认后才能写入个人创作档案。

## 候选稿冻结

进入独立评审前，把当前稿保存为可准确识别的候选版本，并在工作台记录冻结时间、版本名和仍待核事项。评审意见不能直接覆盖候选稿；由用户决定接受哪些意见，再返回共创阶段修改当前稿。
